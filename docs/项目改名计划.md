## 三、不需要改的内容

| 内容 | 原因 |
|------|------|
| Python 包名 `app` | 全项目 import 路径都依赖它，改了崩溃 |
| `ai_tc_` 表名前缀 | 对应 ORM 模型和迁移脚本 |
| `sys_` 表名前缀 | 通用标准前缀 |
| 前端路由路径（`/aitc` 等） | 改了用户收藏链接失效 |
| `VITE_APP_BASE_API=/prod-api` | 与 Nginx 匹配即可 |
| 前端 `src/` 下业务代码 | 不含目录名引用 |

## 四、执行步骤

### 第 1 步：改 `docker-compose.yml`
修改容器名、网络名、数据库名、用户、密码（1 个文件，约 10 处改动）

### 第 2 步：改后端配置
- `app/config.py` — 数据库连接、Redis、邮件
- `app/main.py` — title、description、health
- `pyproject.toml` — name、description、authors
- `.env` — DATABASE_URL、REDIS_URL
- `.env_remote` — DATABASE_URL、REDIS_URL
- `alembic.ini` — sqlalchemy.url

### 第 3 步：改前端配置
- `package.json` — name
- `.env.development` / `.env.production` — 标题确认

### 第 4 步：Git 目录改名
```bash
git mv product_db test_copilot
git mv test_copilot/youlai-fastapi-master test_copilot/backend
git mv test_copilot/vue3-element-admin test_copilot/frontend
```

### 第 5 步：重建数据库容器
```bash
docker compose down -v    # 删除旧容器 + 卷（数据会丢失，需先备份）
docker compose up -d       # 用新配置重建
# 重新导入 SQL
docker exec -i tc-postgres psql -U test_copilot -d test_copilot < sql/schema.sql
docker exec -i tc-postgres psql -U test_copilot -d test_copilot < sql/seed.sql
```

### 第 6 步：重建 Python venv
```bash
cd backend
rm -rf .venv
python -m venv .venv
.venv\Scripts\activate   # Windows
pip install uv && uv sync --frozen
```

### 第 7 步：批量替换文档
`docs/` 下 7 个 `.md` + `plan.md` 中的旧名 → 新名

### 第 8 步：删除旧 README
后端和前端目录下的 README.md / README.en.md 含大量旧名和开源链接，建议删除后重写。

### 第 9 步：验证
- `docker compose up -d` → 容器名变为 `tc-postgres` / `tc-redis`
- 后端启动 → `/health` 返回 `test-copilot`
- 前端构建启动 → 登录 → AI 功能正常

## 五、风险提示

| 风险 | 说明 |
|------|------|
| 数据库数据丢失 | 第 5 步 `docker compose down -v` 会删除数据卷，必须先 `pg_dump` 备份 |
| `.venv` 失效 | 目录改名后旧 venv 的绝对路径引用失效，必须重建 |
| Git 历史 | `git mv` 保留历史，但目录改名后 `git log --follow` 需要 `--follow` 参数 |
| 路径引用 | 文档和脚本中写死的绝对路径（如 `D:\git3\product_db\...`）需要手动改 |
