## 一、项目概览

### 1.1 产品定位

AITC（AI Test Companion）是测试部 AI 助手平台，提供：
- **用例管理**：项目/套件树、用例 CRUD、AI 核心标记
- **AI 任务体系**：挑核心用例、用例审核、脚本生成等 3 类异步任务
- **AI 对话**：SSE 流式聊天，6 个领域技能（字段补全/步骤补写/用例设计 等）
- **辅助数据**：样本库、脚本库、规范管理

### 1.2 技术栈

| 层 | 技术 |
|---|---|
| 前端 | Vue 3 + TypeScript + Element Plus + Pinia + UnoCSS + Vite |
| 后端 | FastAPI + SQLAlchemy Async + Pydantic v2 + Redis + PostgreSQL |
| AI | OpenAI 兼容 API（多模型可配） |
| 部署 | Docker Compose |

### 2.2 后端架构总图

```
main.py ──► app/ai/chat ──► app/ai/agent ──► app/aitc
```

### 2.4 请求全链路（以"挑核心"任务为例）

```
用户发"帮我挑核心用例"
  → 前端 ChatInput 发送 POST /sessions/{id}/messages (SSE)
    → 后端 orchestrator 意图路由 → core_select_skill.execute()
      → task/engine.create_task() 创建异步任务
        → SSE 流式返回"已创建任务"卡片
  → 后端 scheduler 轮询任务表 → 抢占 QUEUED 任务
    → execute_task_bg() → core_select handler 执行（LLM 逐条处理）
      → 任务状态 → COMPLETED
  → 用户在前端任务详情页看到结果 → 确认
    → 前端调用 POST /tasks/{id}/confirm
      → engine 调用 handler.apply_result() → 回写用例核心标记
```

## 三、前端开发指引

### 3.1 页面域标准结构

每个页面域（`case`/`task`/`sample`/`script`/`spec`）遵循统一布局：

```
views/aitc/{domain}/
├── index.vue             # 页面主入口（外壳：组装组件 + 管理状态）
├── components/           # 页面级组件（自动导入，无需手写 import）
│   ├── XxxPanel.vue
│   └── XxxDialog.vue
└── composables/          # 页面级逻辑复用
    └── useXxxPage.ts
```

**组件自动导入规则**：`vite.config.ts` 配置了 `unplugin-vue-components`，`src/**/components` 下的 `.vue` 文件全局自动注册为 PascalCase 组件名。**拆件后无需手写 `import`，直接在 template 中使用**。

⚠️ **命名避免碰撞**：页面域组件命名要注意不与 `src/components/` 下的全局组件重名。建议加域前缀，如 `CaseTable`、`TaskProgress`。

```python
from app.database import Base, TimestampMixin

class AiTcBug(Base, TimestampMixin):
```

```python
from datetime import datetime
from pydantic import BaseModel, Field

class BugCreate(BaseModel):
    title: str = Field(..., max_length=200, description="缺陷标题")
    severity: int = Field(default=2, ge=1, le=4, description="严重程度")

class BugUpdate(BugCreate):

class BugQuery(BaseModel):

    pageSize: int = Field(default=10, ge=1, le=100)
    keywords: str | None = None
    severity: int | None = None

class BugVO(BaseModel):
    id: int | None = None
    title: str = ""
    severity: int = 2
    caseId: int | None = None
    status: int = 0
    createTime: datetime | None = None
    model_config = {"from_attributes": True}
```

#### Step 3：创建 Service

```python
# app/aitc/bug/service.py
"""缺陷域 — 业务逻辑层。"""
from sqlalchemy import func, select
from sqlalchemy.ext.asyncio import AsyncSession

from app.exceptions import BusinessException
from app.pagination import PageResult
from app.response import ResultCode
from app.system.aitc.bug.models import AiTcBug
from app.system.aitc.bug.schemas import BugCreate, BugUpdate, BugQuery, BugVO

class BugService:
    def __init__(self, db: AsyncSession):
        self.db = db

    async def get_page(self, query: BugQuery) -> PageResult[BugVO]:
        conditions = []
        if query.keywords:
            kw = f"%{query.keywords}%"
            conditions.append(AiTcBug.title.ilike(kw))
        if query.severity is not None:
            conditions.append(AiTcBug.severity == query.severity)

        count_q = select(func.count()).select_from(AiTcBug).where(*conditions)
        total = (await self.db.execute(count_q)).scalar() or 0
        offset = (query.pageNum - 1) * query.pageSize
        rows = await self.db.execute(
            select(AiTcBug).where(*conditions)
            .order_by(AiTcBug.create_time.desc())
            .offset(offset).limit(query.pageSize)
        )
        items = rows.scalars().all()
        return PageResult(
            list=[BugVO.model_validate(it, from_attributes=True) for it in items],
            total=total, pageNum=query.pageNum, pageSize=query.pageSize,
        )

    async def get_by_id(self, bug_id: int) -> BugVO:
        obj = await self.db.get(AiTcBug, bug_id)
        if obj is None:
            raise BusinessException(code=ResultCode.DATA_NOT_FOUND, msg="缺陷不存在")
        return BugVO.model_validate(obj, from_attributes=True)

    async def create(self, form: BugCreate) -> BugVO:
        obj = AiTcBug(**form.model_dump())
        self.db.add(obj)
        await self.db.flush()
        return BugVO.model_validate(obj, from_attributes=True)

    async def update(self, form: BugUpdate) -> BugVO:
        obj = await self.db.get(AiTcBug, form.id)
        if obj is None:
            raise BusinessException(code=ResultCode.DATA_NOT_FOUND, msg="缺陷不存在")
        for key, val in form.model_dump(exclude={"id"}).items():
            setattr(obj, key, val)
        await self.db.flush()
        return BugVO.model_validate(obj, from_attributes=True)

    async def delete(self, ids: str) -> int:
        id_list = [int(x) for x in ids.split(",") if x.strip()]
        for iid in id_list:
            obj = await self.db.get(AiTcBug, iid)
            if obj:
                await self.db.delete(obj)
        await self.db.flush()
        return len(id_list)
```

#### Step 4：创建 Router

```python
# app/aitc/bug/router.py
"""缺陷域 — API 路由。"""
from fastapi import APIRouter, Depends
from sqlalchemy.ext.asyncio import AsyncSession

from app.database import get_db
from app.response import Result
from app.system.aitc.bug.schemas import BugCreate, BugUpdate, BugQuery
from app.system.aitc.bug.service import BugService

router = APIRouter(prefix="/bugs", tags=["缺陷管理"])

@router.get("", summary="缺陷分页列表")
async def get_bug_page(
    pageNum: int = 1, pageSize: int = 10,
    keywords: str | None = None, severity: int | None = None,
    db: AsyncSession = Depends(get_db),
):
    query = BugQuery(pageNum=pageNum, pageSize=pageSize, keywords=keywords, severity=severity)
    result = await BugService(db).get_page(query)
    return Result(data=result)

@router.post("", summary="创建缺陷")
async def create_bug(form: BugCreate, db: AsyncSession = Depends(get_db)):
    vo = await BugService(db).create(form)
    return Result(data=vo)

@router.put("/{bug_id}", summary="更新缺陷")
async def update_bug(bug_id: int, form: BugUpdate, db: AsyncSession = Depends(get_db)):
    form.id = bug_id
    vo = await BugService(db).update(form)
    return Result(data=vo)

@router.delete("/{ids}", summary="删除缺陷")
async def delete_bugs(ids: str, db: AsyncSession = Depends(get_db)):
    count = await BugService(db).delete(ids)
    return Result(data=count, msg=f"成功删除 {count} 条记录")
```

### 5.1 三层架构全景

```
┌─────────────────────────── 前端 vue3-element-admin ───────────────────────────┐
│                                                                               │
│  LayoutChat.vue (聊天面板)          views/aitc/task/ (任务列表/详情/审核页)    │
│       │                                    │                                  │
│  useChat.ts (SSE 流)                api/aitc/task/index.ts (TaskAPI)          │
│       │                                    │                                  │
│  ChatMessage.vue (msg_type 渲染卡片)  taskRouter.ts (按任务类型跳审核页)       │
└───────┼────────────────────────────────────┼──────────────────────────────────┘
        │ SSE (chunk/tool_start/tool_end/message/done)   │ REST /api/v1/aitc/tasks
┌───────┼────────────────────────────────────┼──────────────────────────────────┐
│  后端 youlai-fastapi                          │                              │
│       │                                       │                              │
│  ai/chat/ (会话编排)                    aitc/task/ (任务 CRUD + 确认回写)    │
│       │                                       │                              │
│  agent/graph/runner.py (LangGraph SSE)  scheduler.py (DB 轮询抢占任务)       │
│       │                                       │                              │
│  agent/tools/case/ (工具工厂) ──→ 复用 ──→ agent/skills/case/ (业务技能)     │
│                                               │                              │
│                                   agent/tasks/__init__.py (TASK_HANDLERS)    │
│                                               │                              │
│                                   agent/tasks/case/*.py (BaseTask 子类)      │
└──────────────────────────────────────────────────────────────────────────────┘
```

三条核心链路：

1. **Tool 链路（对话内即时执行）**：用户消息 → `AgentRunner.run()` → LangGraph agent 自主调用工具 → 工具薄封装调用 Skill → 返回 `(content, artifact)` → artifact 中的卡片数据经 SSE `message` 事件推到前端 → `ChatMessage.vue` 按 `msg_type` 渲染（`confirm_card` / `draft_card` / `clarify_card`）。

2. **Task 链路（批量异步执行）**：前端或 confirm_card 确认 → `POST /tasks` 创建任务（QUEUED）→ `scheduler.py` 轮询抢占 → `execute_task_bg()` → 从 `TASK_HANDLERS` 取 handler → `handler.execute(ctx)` 逐条调 AI → 完成后前端任务详情页展示结果 → 用户逐条确认 → `apply_result()` 回写业务表。

3. **Skill 层（共享业务逻辑）**：Skill 是"用户意图"的封装，Tool（对话触发）和 Task（批量触发）都复用它，避免业务逻辑写两份。

### 5.2 Task 生命周期

```
QUEUED ──► RUNNING ──► COMPLETED ──► CONFIRMED
                │            │
                └── FAILED ◄──┘
```

| 状态 | 含义 | 触发方 |
|------|------|--------|
| QUEUED | `engine.create_task()` 创建后，等待调度器抢占 | Skill（对话）/ 前端 |
| RUNNING | `scheduler` 抢占成功，`execute_task_bg()` 执行中 | Scheduler |
| COMPLETED | handler `execute()` 完成，等待人工确认 | Handler |
| CONFIRMED | 前端确认，`engine` 调用 handler `apply_result()` 回写业务表 | 前端 |
| FAILED | 执行异常或确认驳回 | Handler / 前端 |

### 5.5 关键设计约定

1. **工具只做薄封装**：业务逻辑必须在 `aitc/*/service.py` 或 Skill 里，工具是把 service/skill 包装成模型可调用的函数。
2. **Task 只管"逐条调 AI + 确认回写"**：调度/进度/日志/重跑都是框架统一处理，handler 不需要关心。
3. **Prompt 工具清单自动生成**：从 `StructuredTool` 的 `name` / `description` 元数据自动拼装，新增工具不需要手改 agent 提示词文件。
4. **Skill 是 Tool 和 Task 的共享业务层**：同一业务意图（如"缺陷分析"）的对话触发（Tool）和批量触发（Task）共用一个 Skill 实现，避免维护两份逻辑。

## 六、Skill 开发指引

### 6.1 Skill 类型

| 类型 | 执行方式 | 示例 | 典型产出 |
|------|---------|------|---------|
| SYNC | 对话内即时执行 | 字段补全、步骤补写、用例设计 | 草稿卡片 |

### 6.2 创建 SYNC Skill

```python
# app/ai/agent/skills/case/summary_skill.py
"""用例摘要生成 — 同步技能。"""
from app.ai.agent.skills.base import BaseSkill

class SummarySkill(BaseSkill):
    name = "case_summary"
    description = "为指定用例生成摘要"
    required_page = "case_detail"
    is_async = False

    async def execute(self, context):
        case_ids = context.get("case_ids", [])
        cases = await self.get_case_service().get_cases_by_ids(case_ids)

        for case in cases:
            summary = await self.client.chat(
                "你是一个测试分析助手，请为以下用例生成一句话摘要。",
                str(case)
            )
            case.summary = summary.strip()

        return {
            "type": "draft_card",
            "title": f"已为 {len(cases)} 条用例生成摘要",
            "data": [{"id": c.id, "summary": c.summary} for c in cases],
        }
```

### 7.3 核心约定

1. **魔法数字归零**：所有状态值使用枚举，不写硬编码数字。
2. **标签映射全局唯一**：`constants.ts` 是唯一来源，不允许在页面内重复定义 `xxxLabel` 函数。
3. **文件拆分时机**：页面 `index.vue` > 300 行时考虑拆组件；模板区块重复出现时立即抽取；跨页面共享逻辑抽取 composable。
4. **URL 不变原则**：后端接口路径 `/api/v1/aitc/...` 作为契约，重构时不动。
5. **git mv 保留历史**：文件移动/改名必须使用 `git mv`，便于追溯 blame。
6. **路由双轨制**：列表页由后端 `sys_menu` 表动态注册；详情子页面在 `router/index.ts` 静态注册（`meta.hidden: true`），改名需同步改后端菜单 component 字段。
7. **后端路由注册顺序**：固定路径必须在参数路径前注册（如 `/cases/pending-tree` 先于 `/cases/{case_id}`）。

## 八、Skill 与 Task 关系总结

| | Skill（技能） | Task（任务） |
|---|---|---|
| 本质 | 对话里的一个**意图处理器** | 批量**异步作业** |
| 触发 | 用户发消息，意图路由命中 | 调度器轮询抢占 |
| 生命周期 | 一次问答 | QUEUED→RUNNING→COMPLETED→CONFIRMED |
| 产出 | 草稿卡片 / 任务卡片 | task_items 结果，人工确认回写 |
| 代码位置 | `app/ai/agent/skills/` | `app/ai/agent/tasks/` |

**调用关系**：
- **Skill → Task**：ASYNC 技能调用 `engine.create_task()` 发起任务
- **Scheduler → Handler**：scheduler 抢占 QUEUED 任务后调用 `execute_task_bg()` 执行 handler
- **前端 → Task 业务**：任务列表/详情/确认等管理操作通过 `aitc/task/router.py`
- **Handler → 业务 Service**：task handler 通过 aitc 各域 Service 读写业务数据
- **Task 业务 → Handler**：`engine` 确认回写时按任务类型分发到 handler 的 `apply_result()`
